# ADS 对比总结（MPT / MEST / AccTrie）

## 实测性能（100 节点，小 workload，release）
- MPT: 吞吐 **824.37 ops/s**，平均延迟 **1.213 ms**，P95 1.726 ms，P99 2.298 ms（日志: `logs/system_test_mpt_20251205_042649`）
- MEST: 吞吐 **879.98 ops/s**，平均延迟 **1.136 ms**，P95 1.588 ms，P99 2.120 ms（日志: `logs/system_test_mest_20251205_042804`）
- AccTrie: 吞吐 **29.19 ops/s**，平均延迟 **34.26 ms**，P95 48.94 ms，P99 50.91 ms（日志: `logs/system_test_acctrie_20251205_042408`）

## 数据结构与特性对比
- MPT: 前缀压缩 Trie + Merkle 哈希；证明 O(log n) 哈希，验证为哈希拼接；更新需沿路径重哈希，路径并行性一般。
- MEST: 分段/分桶 + 段内 Merkle + MGT；证明仍 O(log n) 但常数略大；哈希验证，分段有利并行与局部性。
- AccTrie: 叶子带 BLS12-381 累加器，成员证明与集合大小无关；证明含群元素，序列化大；验证/更新需累加器群运算，常数成本高。

## 优劣概览
- 性能: MEST ≥ MPT ≫ AccTrie（当前实现）。
- 证明大小与验证成本: MPT/MEST 小且轻；AccTrie 大且重（群运算+序列化）。
- 并行/扩展: MEST 分段并行性好；MPT 路径并行受限；AccTrie 理论可批并行，但需额外工程优化。
- 适用场景: 
  - MPT: 通用 KV/状态，读多写中等，带宽敏感。
  - MEST: 需要更好并行与局部性的批量读写。
  - AccTrie: 需要累加器特性（集合证明与大小无关、潜在批量合并）且能接受更高计算成本。

## AccTrie 可能的优化方向
- storager 侧插入/验证并行化（Rayon 等），批内多线程累加器计算。
- 降低序列化/拷贝：紧凑编码、缓存中间值。
- 批策略：更多批量合并、单次快照、按需/抽样验证以平衡安全与性能。
- 硬件/并发：更高核数和多客户端并行以摊薄单次成本。
